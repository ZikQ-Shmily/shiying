# 拾影 · 媒体资源管理

自部署的多用户网页，使用 EMBY 账号登录，管理 EMBY 资源的固定来源、版本、追更和入库进度。支持手机与电脑；无需把媒体文件上传到管理服务。

界面采用浅色液态玻璃风格：悬浮导航、冰蓝渐变背景、半透明材质与圆润控件。表格和表单保留清晰底色，兼容窄屏、减少动态效果及不支持背景模糊的浏览器。

## 当前能力

- 管理作品与季，保存原帖、分享者、115 链接、提取码和版本。
- 每部作品可保存多个来源，切换当前来源时旧来源仍保留。
- 来源集数和入库集数分别记录。输入 `1-8,10-12` 会保留第 9 集的缺口；单填 `12` 仅表示第 12 集。
- 自动区分追更、待补集、今日开播、尚未播出、待找资源、已完成与来源异常。
- 待处理集中显示缺集、来源异常和同步失败；时区为上海。
- 登录保护、密码修改、回收站、JSON 导出和导入恢复。
- 支持 TMDB 搜索确认作品和季，再添加追更；按 TMDB ID 与 EMBY 精确匹配，后台定时对比入库集数。
- RE0 来源和固定发布者由 CMS 联动维护；支持网盘集数识别、首次绑定立即转存，以及新追更邮件提醒。

## 账号与权限

登录页支持「EMBY 账号」和「本地管理员」。首次使用先以原有本地管理员登录，在设置保存 EMBY 地址（支持 HTTP / HTTPS）、API Key 和 TMDB 凭据；此后用户直接使用 EMBY 的用户名、密码登录，无需另外注册。

- EMBY 管理员进入完整管理后台；普通用户进入个人追更页面，只能搜索、提交、查看和取消自己的追更。
- 普通用户的「我的追更」展示尚未收齐的有效追更及进度概览；「提交记录」以列表显示各作品的最近一次提交，支持状态筛选；「已收齐」只展示 EMBY 已确认整部或整季收齐的有效追更。
- 后台保留资源来源、链接、版本、同步、备份、回收站和连接设置，并可在「用户与提交」读取 EMBY 用户及追更数量。概览展示待办、统计和最新一条动态摘要，点击后查看近期动态；完整资源搜索、筛选和表格统一放在「全部资源」。
- 同一 TMDB 作品、类型与季合并管理，记录每位提交用户的 EMBY 服务器 ID、用户 ID、用户名、提交时间与取消状态；重命名后仍关联同一用户。旧记录保持原样，不推测历史提交人。
- 用户取消自己的追更不会删除作品或其他用户的提交。重新提交会恢复个人追更；管理员暂停的作品仍保持暂停。
- 登录由 EMBY 用户认证接口校验，系统不保存 EMBY 密码；服务端加密保存本次用户令牌，退出时撤销该令牌。权限、禁用状态和令牌有效性最多约一分钟重新检查一次。核验失败期间不授予访问权限。
- 普通用户 API 响应仅包含自己的作品与进度，不返回来源链接、提取码、管理备注、其他提交人或服务凭据。本地管理员入口继续保留，方便连接维护。

## TMDB 与 EMBY 连接

在“设置与备份”填写 TMDB API Read Access Token（或 v3 API Key）、EMBY 访问地址（HTTP 或 HTTPS）和 API Key，保存后分别测试。地址应包含实际 API 前缀，例如 `http://服务器IP:8096` 或 `https://emby.example.com/emby`（若服务部署在根路径则不加 `/emby`）。连接不会跟随重定向或忽略证书错误。网页不会回显密钥，留空表示保留现有凭据。

搜索中文片名，确认年份、作品和季后添加追更。每个作品/季独立管理，同一 TMDB ID、类型、季号不会重复添加。TMDB 作品信息只读，绑定 RE0 后自动维护原帖、115 链接、发布者与版本；手动来源可自行补充。详情显示追更、来源变更、检查和入库同步轨迹。单部作品可暂停追更。

默认每 30 分钟后台自动同步，可设置为 15～1440 分钟；也可单部或全部立即同步。即使浏览器关闭，Docker 容器中的调度器仍运行。部署配置固定单 Gunicorn worker，避免多进程重复调度；线程用于并发请求。

缺集按上海日期计算：TMDB 有效播出日期早于今天的集号（加上网盘自动识别或手动确认的来源集号），减去实际入库集号。未来播出或日期未知的集数不按 TMDB 计为已播缺集。TMDB 播出日期并不保证分享者已有该资源。EMBY 根据 TMDB ID 精确匹配，过滤虚拟缺失项，展开一个文件包含多集的编号并去重；STRM 等媒体索引也属于入库，本系统不验证实际播放质量。

查询成功且库中没有作品时显示尚未入库；发现同名作品但 TMDB ID 不一致时提示核对刮削；连接失败时显示同步失败并保留上次进度，不会清空入库记录。成功匹配后以 EMBY 集表更新入库进度。EMBY 项目若缺少正确 TMDB ID，请先在 EMBY 修正刮削信息。

Emby 只读 API 请求遇到超时、连接中断或 HTTP 408/502/503/504 时，等待 1 秒后重试一次，每次超时 12 秒；凭据、证书、无效响应等错误不重试。登录、解锁和转存请求不使用这项重试策略。最终失败会在作品详情及新动态中记录原因，容器日志记录操作类型、错误分类、尝试次数及总耗时，不记录服务地址、作品 ID、查询参数或密钥。若填写 CMS 的代理地址，Emby 比对也会依赖该代理；可使用同一 Emby 服务器的直接地址减少中间环节。

连接凭据采用 AES-GCM 加密存入数据库，密钥由 `.env` 的 `SECRET_KEY` 派生。迁移完整配置时必须同时保留数据库和原 `SECRET_KEY`。JSON 资源备份不包含连接凭据，恢复后需要重新配置；提交用户、TMDB 关联和流程记录会保留，EMBY 结果重新核对。

TMDB Logo 使用其官方开发者文档提供的 `https://files.readme.io/29c6fee-blue_short.svg`，原样保存在 `static/tmdb-logo.svg`。This product uses the TMDB API but is not endorsed or certified by TMDB.

## 首次部署

镜像由 GitHub Actions 自动测试、构建并发布到 `ghcr.io/zikq-shmily/shiying`，支持 `linux/amd64` 与 `linux/arm64`。服务器只需 Docker Engine、Docker Compose 与 OpenSSL；本地电脑无需安装 Docker。

服务器在一个新目录下载部署文件：

```sh
curl -fsSLO https://raw.githubusercontent.com/ZikQ-Shmily/shiying/main/compose.yaml
curl -fsSLO https://raw.githubusercontent.com/ZikQ-Shmily/shiying/main/deploy.sh
curl -fsSLO https://raw.githubusercontent.com/ZikQ-Shmily/shiying/main/backup.sh
curl -fsSLO https://raw.githubusercontent.com/ZikQ-Shmily/shiying/main/update.sh
```

执行首次部署：

```sh
sh deploy.sh
```

访问 `http://服务器IP:8787`。用户名默认为 `admin`；初始密码在服务器的 `.env` 文件中：

```sh
sed -n '/^ADMIN_USERNAME=/p; /^ADMIN_PASSWORD=/p' .env
```

`.env` 包含服务密钥，仅限管理员读取，不应上传或分享。`ADMIN_PASSWORD` 仅用于空数据库首次初始化；之后在网页设置中改密码。修改此环境变量不会重置现有账号密码。

## 管理

```sh
docker compose ps
docker compose logs --tail=100 web
docker compose restart
sh update.sh
```

数据在 `data/media.sqlite3`，容器更新和重启均保留。不要删除 `data/`。不要把数据库放入公开 Web 目录。

Emby、TMDB、CMS/RE0、SMTP 的个人地址与凭据均在启动后从管理页填写，保存到挂载的数据库；API Key、SMTP 授权码等凭据加密保存。构建和发布流程不接收这些配置。`.env` 只在服务器生成，用于初始账号、会话/加密密钥、端口等运行参数；不会上传 GitHub 或打进镜像。

更新时保留原 `.env`、`SECRET_KEY` 与 `data/`，无需重新填写连接。`sh update.sh` 会先拉取镜像、备份数据库，再替换容器。需要固定或回退版本时，在 `.env` 中设置 `SHIYING_IMAGE=ghcr.io/zikq-shmily/shiying:sha-完整提交SHA`，再执行更新；数据库结构发生变化时先核对兼容性，必要时连同备份恢复。

生产配置不包含 `build`。需要自行从源码构建时显式使用：

```sh
docker compose -f compose.yaml -f compose.source.yaml up -d --build
```

## GitHub 构建与配置边界

推送 `main`、`v*` 标签或手动运行工作流后，先执行后端、前端与发布文件检查，再启动临时容器验证空配置、运行时填写配置和替换容器后的持久化，最后发布多架构镜像。`latest` 指向通过检查的主分支构建，另提供完整提交 SHA 标签。构建所用的 `GITHUB_TOKEN` 是 GitHub 临时提供的发布令牌，与个人接入配置分开。

Docker 构建采用文件允许列表，只包含应用源码、依赖列表与公开静态资源。`.env`、数据库、备份、测试文件、Git 元数据与本地联调记录不进入镜像；个人配置与本地联调记录也不进入 Git 仓库。镜像检查会验证这些边界。

## 备份与恢复

网页的“导出备份”下载所有记录，包括回收站、原始来源、提取码和集数；不包含账号密码或会话。在另一个空实例“导入备份”即可恢复记录。相同 ID 的现有记录会跳过，导入不会覆盖已有内容；导入前整份校验，任何无效记录会阻止本次导入。

完整数据库一致性备份：

```sh
sh backup.sh
```

备份保存在 `data/backups/`，包含账号密码哈希及管理数据。恢复完整数据库时先停止容器，将选定备份复制成 `data/media.sqlite3`，同时移走旧 `media.sqlite3-wal` / `media.sqlite3-shm`，校正所有者为 `10001:10001`，再启动容器。操作前保留当前数据目录副本。

## 域名与 HTTPS

IP 直连默认使用 HTTP。正式保存资源提取码前，建议配置域名和 HTTPS 反向代理。届时将 `.env` 中 `BIND_ADDRESS` 改为 `127.0.0.1`（反向代理与本机部署时），并设 `COOKIE_SECURE=true` 后重新创建容器。代理需要保留原始 Host。EMBY 连接凭据在“设置与备份”中单独配置，仅用于读取与比对媒体库。

## 连接状态

管理员左侧显示 Emby、TMDB、CloudMediaSync 三个连接的名称与 API 检测结果，每分钟自动检查，地址在设置页查看。RE0 查询、解锁与固定来源订阅均使用用户自己的 CMS。CMS 健康检查同时确认本机 RE0 授权和固定来源保护；状态检查不解锁资源或创建下载任务，连接详情仅管理员可见。独立查询端仅作为旧配置的兼容模式保留。

## 新追更邮件提醒

在管理员「设置与备份 → 新追更邮件提醒」填写收件邮箱、发件邮箱、SMTP 服务器、端口、用户名与授权码，发送测试邮件确认后开启。支持 SSL/TLS 和 STARTTLS；授权码加密保存，不会返回网页。邮件可附上你填写的网站地址。

普通用户首次提交作品或某一季、其他用户追更已有作品、取消后重新提交时发送提醒。同一用户重复点击提交不重复发信；管理员添加、自动同步及已有历史提交不会触发通知。邮件包含提交用户、作品、季数及时间，不包含网盘提取码或 API 密钥。

提交与待发送通知一起保存，后台异步发信，关闭网页后仍有效。发送失败自动重试，重启后继续处理；设置页显示最近发送结果及失败数量，可手动重试。关闭通知或更换收件邮箱会取消尚未开始发送的旧通知。邮件送达以收件服务为准；SMTP 超时或发送中断恢复时，极少数情况可能出现重复邮件。

网页 JSON 备份仅导出资源记录，邮件配置及队列随完整数据库备份保留；恢复加密授权码时须使用原 `SECRET_KEY`。

## 自动状态

已入库覆盖已知总集数时视为完成；总集数未知时，必须有入库记录、没有待补集并勾选“确认全集已入库”才完成。电影使用单项入库进度。管理员“待处理”自动汇总正在追踪作品的已确认缺集、当前来源异常与同步失败，可按处理类型筛选。TMDB 作品在 Emby 已匹配，或按 ID 与名称查询后确认库中未找到时，才确认缺集，已播按北京时间昨日及以前的 TMDB 排期估算；当天排期单列“今日排期”，首播当天显示“今日开播”（电影为“今日上映”），不凭当天日期计入已播或缺集，后续和日期待定的集数另计。来源明确已有的集数仍可参与入库比对；暂停追更不计入待处理。问题解决并同步后自动移出，原人工复查日期仅保留为历史记录，不触发待办。

### RE0 / CloudMediaSync 来源追踪

管理员通过 TMDB 添加作品后选择 RE0 条目，按发布者、版本筛选 115 来源。选择后自动保存来源信息，并向执行端下发作品、季数、条目、固定发布者。收费条目由管理员按显示的积分显式解锁；查询端执行前核对价格上限。网站定时检查和 CMS 订阅查源均不带购买授权，只使用免费或已解锁资源，不自动换条目或发布者。

当前使用单 CMS 模式：网站配置 `re0_via_cms=true`，查询与订阅统一复用 `cms_url/cms_token`。`deploy/cms_bridge.py` 与 `deploy/cms_executor.py` 一起安装在用户自己的 CMS 插件中；查询端点 `/api/shiying` 使用已有 `/config/shiying-executor.token` 鉴权。OAuth 令牌留在该 CMS，由 CMS 管理刷新。网站与 CMS 均已移除对旧查询实例的活动配置。旧的 `re0_gateway_url/re0_gateway_token` 和独立桥接密钥仅为兼容分离模式。

`deploy/install_executor.py` 负责校验语法、备份原文件并将两个适配模块安装到增强插件。单 CMS 模式下，权限为 600 的 `/config/shiying-executor.json` 仅保存 `query_mode="local"` 与 `public_gateway_url`（本机 CMS 的公开地址，须与网站 CMS 地址一致），不保存其他实例的地址或凭据。本机查源直接调用进程内 RE0 客户端，失败时不会回退到其他 CMS。RE0 账号在这台 CMS 内完成授权。

执行端在 CMS 原生媒体订阅中创建记录，先保存并读回 `hdhive_author` 与发布者规则，再激活订阅。逐季固定条目保存在 CMS 配置 `cms_shiying_subscriptions_v1` 中；同一作品的多个季可用不同发布者，CMS 查源只解析登记的条目。拾影管理的订阅会屏蔽其他虚拟来源和原生 Telegram 来源，网关故障时不回退到其他发布者。若 CMS 已存在独立维护的同一作品订阅，拒绝覆盖并在网站提示下发失败。

暂停作品、解绑来源、移到回收站会下发该季暂停；同作品仍有其他活动季时，CMS 的整部作品订阅继续运行。失败保留来源并进入待处理，详情可重试下发，后台同步也会重试。恢复记录会恢复下发。网站显示“已下发”只表示 CMS 已接收规则，实际下载与入库结果以 CMS 和 Emby 为准。备份包含 RE0 绑定但不导出密钥；恢复后的下发状态重新确认。CMS 插件升级时应保留适配模块，覆盖前备份。

普通用户不能访问来源、下发控制或连接设置。


### 2026-10-23 界面与片库状态

- TMDB 季选择使用可键盘操作的单选卡片，只有一季时默认选中，保留季号、集数与首播日期。
- 管理员侧栏只显示服务名称与实时状态；地址继续保留在设置中。
- Emby 先按 TMDB ID 匹配；没有结果时再按作品中文名、原名查询。两者均查不到且无历史入库记录时，标记 `absent`，显示正常的等待入库。存在同名或相似作品的标识冲突、历史进度冲突时保留 `unmatched` 供核对；连接失败为 `error`，不会清空已有进度。
- 今天有首播排期且此前没有已播集数时，状态为 `premiering`。当天排期不据此直接加入缺集，避免在实际放映前提前报缺集。
- 手机端资源和提交历史采用卡片布局，详情比对纵向排列，弹窗内容区滚动并保留底部操作；输入字号与触控区域适配手机，支持安全区边距。
- `static/logo.svg` 用于应用标志与 SVG 标签图标，另有 32px PNG 标签图标和 180px Apple touch icon。
